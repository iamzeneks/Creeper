# 📦 Creeper — Steganography Tool User Manual

**English** | [简体中文](使用说明书.md)

> **Quietly hide any file inside images and music**!
> Version v1.0 | Platform Windows | No third-party dependencies, pure hand-written C++

---

## ✨ What Is This

A suite of encrypted steganography tools **disguised as format-conversion software**, containing two programs:

| Program | Disguise Identity | Real Identity |
|--------|------------------|---------------|
| `creeper_img.exe` | 格式转换大师 v3.2 (Image Converter) | Image steganography: hide files inside PNG |
| `creeper_audio.exe` | 音频转换专家 v2.8 (Audio Converter) | Audio steganography: hide files inside MP3 / WAV |

After hiding:

- 🖼 **The image displays normally**, visually indistinguishable (pixel values change by at most ±1, a color deviation of 1/255; after embedding, histogram compensation is automatically applied, making it even harder to detect statistically)
- 🎵 **The music plays normally**: MP3 audio data is not touched at all (only the MPEG frame header auxiliary bits are rewritten, so the decoded result is identical); WAV only changes the lowest 1/2/3 bits of each sample (standard-tier deviation 1/32768, inaudible)
- 🔐 The hidden content is **AES-256-GCM encrypted**; without the password no one can read it

## 🚀 Quick Start

### Normal Usage (the Disguise Layer)

It's just an ordinary format converter:

1. Open the program → click "添加文件" ("Add Files") to select images/music
2. Select "输出格式" ("Output Format") and "输出目录" ("Output Directory")
3. Click "开始转换" ("Start Conversion") → done

Image conversion is **real conversion** (JPG↔PNG are actually transcoded); audio just changes the extension (most players still play it fine).

### Hidden Usage (Encrypt/Decrypt)

**Core mnemonic: `press Ctrl+Shift+F to bring up the metadata window → fill in the password in the designated field → click OK → click Convert`**

| Program | Window Brought Up | Password Hidden In | Other Fields |
|---------|-------------------|--------------------|--------------|
| creeper_img | "EXIF 信息" ("EXIF Info") | **镜头格式** ("Lens Format") | Maker/Model/Aperture/Shutter… all prefabricated fake data |
| creeper_audio | "ID3 标签" ("ID3 Tags") | **流派** ("Genre") | Title/Artist/Album/Year… all prefabricated fake data |

> The metadata window looks like an EXIF/ID3 editor, but in reality it **does not modify any real file** — it just records the password in memory. After clicking "确定" ("OK") the password is placed, and clicking "开始转换" ("Start Conversion") is the key action.

## 🔒 Encryption: Hiding a File Inside a Carrier

Using an image as an example (audio is the same):

1. **Add two files** to the list:
   - First = carrier (the image to hide into, e.g. `img.png`)
   - Second = payload (the file to hide, e.g. `src.png`)
2. Press `Ctrl+Shift+F` → fill in the password in "镜头格式" ("Lens Format") → click "确定" ("OK")
3. Click "开始转换" ("Start Conversion") → `宿主名_已转换.png` (`carrier_name_converted.png`) is generated in the output directory

> With only **one carrier + one payload** (two files), whether or not "硬件加速" ("Hardware Acceleration") is checked makes no difference — it always performs encrypted embedding.

**This new PNG is your carrier**: it can be viewed and shared normally, and it contains the encrypted complete file.

### 🧩 Large Files: Split Into Multiple Parts (Sharding)

When a single carrier can't fit it, you can **split it into multiple parts and hide them in multiple carriers**:

1. **Add N+1 files** to the list: the first N = carriers, **the last = the large file to hide** (use the "上移" ("Move Up")/"下移" ("Move Down") buttons to move the large file to the end of the list)
2. **Check "硬件加速" ("Hardware Acceleration")** (encryption mode)
3. Press `Ctrl+Shift+F` → fill in the password → click "确定" ("OK") → click "开始转换" ("Start Conversion")
4. Each carrier's `宿主名_已转换.<ext>` is generated in the output directory

**When retrieving**: add **all** of these `carrier_name_converted` files to the list (3 or more, order-independent), **do not check "硬件加速" ("Hardware Acceleration")**, fill in the same password, click "开始转换" ("Start Conversion") → the original file appears in the output directory.

> Encrypt the whole thing first, then split: any single part is a meaningless ciphertext fragment, **you must collect all of them to restore** — even if one part is taken by someone, no information can be extracted from it.

> When "硬件加速" ("Hardware Acceleration") is unchecked, 3 or more files are always treated as "decrypt & merge" (2 files are treated as single-carrier embedding); **without a password, multiple files just fake a batch conversion**, nothing actually happens.

### 📏 Capacity Limits

| Carrier | Hidable Size | Note |
|---------|--------------|------|
| PNG image | **default ≤ 15% of capacity** | e.g. a 2560×1600 image, 15% ≈ 230 KB (adjustable via CLI) |
| WAV audio | **default ≤ 15% of samples×depth/8** | 44.1kHz stereo per minute ≈ 99 KB (default) ~ 1.98 MB (100% + depth 3); **preferred for large files** |
| MP3 audio | **frames×3÷8 bytes** | 3 bits per frame, e.g. a song with 19,194 frames ≈ 7.2 KB (about 3 pages of text) |

- Before hiding, the tool automatically compresses; what can be compressed (text, documents, uncompressed formats) actually takes up less space
- PNG/WAV by default **use only 15% of the carrier's capacity** (a conservative line against statistical detection); exceeding it reports an error; if you really need more, use the CLI `--cap` to raise it
- **For large files use WAV as the carrier**: a 60-second WAV can hide about 99 KB by default (nearly 1.98 MB after raising the cap); MP3's capacity is measured in KB and only suits small files; PNG is a compressed format and large files will exceed capacity and error out
- The less you hide, the harder it is to detect: under the 15% default cap, statistical detection is essentially imperceptible

#### 🎚 Adjusting Tiers (GUI without the CLI)

There are two dropdowns at the bottom of the `Ctrl+Shift+F` hidden window; after clicking "确定" ("OK") they take effect for this conversion (applies to both single-carrier embedding and multi-file sharding):

| Dropdown | Tier | Effect |
|----------|------|--------|
| **编码质量** ("Encoding Quality") | 标准 (Standard) / 高 (High) / 超高 (Ultra) / 极限 (Extreme) | Fill-rate cap 15% / 30% / 50% / 100% (equivalent to CLI `--cap`) |
| **位深** ("Bit Depth") (audio only) | 标准16bit / 高24bit / 超清32bit | WAV changes 1 / 2 / 3 bits per sample, capacity ×1 / ×2 / ×3 (equivalent to CLI `--depth`) |

- "标准" (Standard) = the most covert default value; "极限" (Extreme) + "超清" (32bit) = maximize capacity (e.g. 1 minute of WAV goes from about 99 KB to nearly 1.98 MB)
- **The higher the tier, the easier to be found by statistical detection** — capacity is not free; hiding more and hiding stably are mutually exclusive

### 🔓 Decryption: Taking the File Out

1. **Add one file** = the carrier with a payload (e.g. `img_已转换.png`)
2. Press `Ctrl+Shift+F` → fill in the **same password** → click "确定" ("OK")
3. Click "开始转换" ("Start Conversion") → the **original file** appears in the output directory (even the filename is restored)

> A wrong password prompts "转换失败：密码错误或文件已损坏" ("Conversion failed: wrong password or file corrupted") — the UI text always looks like an ordinary converter and never exposes the steganography functionality.

## 🧠 Technical Principles

```
payload file → zlib compression → AES-256-GCM encryption → envelope (magic+salt+nonce+ciphertext)
                                    ↓
PNG carrier: envelope scattered into RGB pixels at password-derived random positions (±1 embedding + histogram compensation)
WAV carrier: envelope scattered into the lowest bits of samples at password-derived random positions (1–3 bits per sample, depth adjustable)
MP3 carrier: envelope scattered into the auxiliary bits of each MPEG audio frame header (3 bits per frame, audio untouched)
```

- 🔑 **Key derivation**: PBKDF2-HMAC-SHA256, 600,000 iterations, brute force is unrealistic
- 🛡 **Integrity**: GCM authentication tag — wrong password or tampered file triggers an immediate error, never decodes into garbage
- 📷 **Invisibility**: only nudges pixel values by ±1, a color change of 1/255, imperceptible to the human eye; after embedding, histogram pairing compensation is automatically applied to pull the statistical distribution back to its original shape
- 🎵 **Inaudibility**: MP3 audio data is not touched at all, the decoded result is identical to the original file; WAV only changes the lowest 1/2/3 bits of each sample (standard-tier deviation 1/32768 ≈ -90dB, inaudible; 32-bit-tier deviation ≤7/32768 ≈ -73dB)
  - Why MP3 and WAV hiding differs: WAV is lossless "raw samples", the lowest bits can be changed freely; MP3 is an already-compressed data stream, changing any single bit causes a burst of noise, so only those flag bits in the frame header that decoders never use (the auxiliary bits) can be changed
- 🧪 **Cross-validation**: the encryption envelope inter-operates with the Python `cryptography` library (standard RFC1950/RFC1951)

## ⚠️ Notes

1. **Forgotten password = data permanently lost**. No backdoor, no recovery; AES-256 is not for show
2. **Without the password it is "invisible"**: there is no fixed marker in the carrier file; only the correct password can prove something is hidden inside; the password itself is the "detection switch" — **do not write the password next to the file**
3. **Hiding is not absolutely safe**: statistical detection methods (histogram/chi-square analysis, etc.) can raise the probability of suspicion; this tool's ±1 embedding and histogram compensation already push the traces very low, but the less you hide the harder it is to detect; this only guards against "casual glances", not "professional forensics"
4. **Carrier selection**: use photos you took yourself, with texture and noise, for best results; solid-color/gradient images tend to give it away. **Never use images searchable online** — the other party can compare against the original and immediately expose it
5. **Secondary compression/transcoding of the carrier will destroy the hidden data** (e.g. converting PNG to JPG)
6. **MP3 carriers are exactly the same size before and after hiding** (only frame header auxiliary bits are changed); WAV/PNG carrier sizes stay the same or change only slightly after hiding (WAV is byte-for-byte the same size; PNG changes compression ratio when pixels change), mind the proportions
7. **The "访问官网" ("Visit Website") button on the About page is a self-destruct button**: clicking it and confirming will make the program exit and delete its own exe (anti-search function) — don't click it in daily use

## 🛠 Command-Line Tool (Advanced)

`creeper_cli.exe` provides an interface-free operation, convenient for scripting:

```bash
creeper_cli seal <input-file> <output-envelope> <password>               # encrypt only
creeper_cli open <envelope> <output-file> <password>                     # decrypt only
creeper_cli embed <carrier> <payload> <output> <password> [--cap N]      # encrypt+hide (N=PNG/WAV fill-rate cap %, default 15)
creeper_cli extract <carrier> <output-dir> <password>                    # extract+decrypt
creeper_cli has <carrier> <password>                                     # detect whether it contains a payload (1/0; wrong password or no payload both yield 0)
creeper_cli split <large-file> <password> <output-dir> <carrier...>      # split across multiple carriers (preferred for large files)
creeper_cli unsplit <output-dir> <password> <carrier...>                 # merge multiple carriers to restore (order-independent)
```
