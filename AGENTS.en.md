# Creeper — Agent Guide

**English** | [简体中文](AGENTS.md)

A C++17 steganography suite on Windows: encrypt files and hide them inside PNG / MP3 / WAV. The authoritative specifications are in `docs/PROMPT_ENCODER.md` / `docs/PROMPT_TESTER.md` (encoder/tester task books), results and known defects in `docs/TEST_REPORT.md`, and product documentation in `docs/使用说明书.md` / `docs/技术报告.md`.

## Build & test

- Build: `src/build.bat` (ASCII-only) builds the three exes into `res/` (the release package) in one shot, requiring w64devkit's `g++` on PATH. The GUI exe uses `-mwindows`; the CLI does not.
- You must build before testing; temporary files go in `tests/tmp/`:
  - `python tests/test_crypto.py` (crypto round-trip + robustness)
  - `python tests/test_png.py` / `python tests/test_mp3.py` / `python tests/test_wav.py` (stego round-trip)
  - `python tests/test_cross.py` (C++ ↔ Python envelope interoperation, critical)
  - `powershell -ExecutionPolicy Bypass -File tests\test_gui.ps1` (GUI smoke, pops a window for 3 seconds and kills the process)
  - `powershell -ExecutionPolicy Bypass -File tests\test_gui_about.ps1` (About dialog real click chain, copy of the exe)
  - `powershell -ExecutionPolicy Bypass -File tests\test_gui_quality.ps1` (hidden window「编码质量」"encoding quality" OCR verification)
  - One-shot full run: `tests\run_all.bat` (9 suites serial, any failure exits non-zero)
- Test dependencies: Python 3.14 + Pillow + numpy + cryptography; `tests/tester.py`'s `ROOT` has been made relative (the repo is movable) and `summary()` auto-archives results to `tests/results/`; `tests/envelope.py` is the local copy of the envelope reference implementation (test_cross prefers local); test carriers are in `assets/` (`img.png` / `msc.mp3` / `test.wav`, generated uniformly by `tests/gen_hosts.py`, each auto-generated when missing: W0 calls `gen_wav.py`).
- Do not report known issues as new bugs: OBS-2 is fixed (`crypto.cpp` DEFLATE upgraded to LZ77 + three-way block encoding: fixed/dynamic Huffman/stored block, shortest wins, converging with Python zlib; the 1.9× on extreme repetitive text is an LZ77 match-strategy difference, not a defect). Historical defect BUG-1 (ID3v2 tag size +10 bytes) is fixed; OBS-1 (`has` returning 0 for an empty file) has been formalized with the no-magic refactor (empty file = no payload = 0, reasonable semantics). Changes to the relevant code must sync-update TEST_REPORT.md.
- The GUI window is fixed-size (not resizable/maximizable), scaled by system DPI (`common_ui.cpp` `ui_run`, logical 1000×640 × `GetDpiForSystem()/96` physical pixels, falls back and centers when exceeding the work area); when changing layout, ensure the main view fills the client area (`vp-2` + `NoResize|NoMove|NoCollapse`), always keep control labels on the left (`Text` + `##` hidden label), and do not revert to freely resizable style.

## Hard constraints

- **Do not modify `third_party/stb/` and `third_party/imgui/`, and do not introduce new dependencies** (system libraries + existing third-party only).
- The project is a git repository (BSD 3-Clause); `res/` (release package: 3 exes + md manual copy) is a deliverable (already excluded by .gitignore, not in the version-control tree) — don't delete or mess with it, and after exe changes sync `res/` and the portable edition (the portable zip is deprecated and no longer packaged); documentation deliverables = the markdown sources under `docs/` (`使用说明书.md` / `技术报告.md`), no PDF output.

## File formats (any change to one must stay byte-compatible with the reference implementation)

- **Crypto envelope** (`crypto.h/cpp`): 41-byte header `CREEPER1` + ver 0x01 + salt(16) + nonce(12) + ct_len big-endian(4), followed by AES-256-GCM ciphertext (including 16B tag); PBKDF2-HMAC-SHA256 600,000 iterations; DEFLATE compression before seal (RFC1950 zlib, decodable by Python zlib). **Must interoperate with the Python envelope reference implementation (`tests/envelope.py` local copy)** — test_cross depends on this compatibility. The envelope header magic string exists in the source as a XOR-0x55 byte array (`xstr()` restores it at runtime), so there is no plaintext `CREEPER1` in the exe.
- **PNG** (`png_steg.cpp`): only embed 1 bit into each of the three RGB channels (alpha stays unchanged); the stego header has **no magic bytes** = name_len(2B BE) + UTF-8 original filename + env_len(4B BE) (**no seed field** — the scatter seed is derived from the password: `crypto_steg_seed(password, "creeper-seed")` = HMAC-SHA256(password, tag) first 4B, lightweight derivation, seed is non-secret); the header+envelope as a whole is scattered by the seed (xorshift64 + linear probing, a **purely content-independent sequence** — a "texture-mask adaptive embedding" was once attempted, but a ±1 modification changes the neighbor diff by up to 2, and any content threshold has a fuzzy band that flips the mask, making the sequence unreplayable — mathematically infeasible, abandoned); **payload presence = GCM authentication passes when the password is correct** (`png_has_payload(path, password)` fully parses + authenticates; wrong password / no payload both return false), false-positive probability 2^-128. **Embedding uses ±1 (LSB matching, not forced LSB)**: when a bit mismatches, the pixel is changed by ±1 (random direction, single direction at the border); after embedding, histogram pairing compensation uses non-carrying pixels to pull the modified histogram back to its original shape, avoiding histogram step features. **Self-adversarial re-embedding**: after compensation, compute the RGB aggregated histogram L1; if `L1 > modified pixel count × 15%`, restore the original image from the undo snapshot and re-embed (up to 3 tries; the undo log must NOT have a hard cap — truncation would leave dirty pixels from incomplete restoration); before writing to disk, **replay the extraction sequence bit-by-bit for self-check** (report an error on mismatch). The extraction side only reads the carrying-bit LSB, unaffected by compensation. **Fill-rate cap**: `png_embed(..., fill_limit_pct)` defaults to 15% (anti-statistical-detection); on exceeding it, report `payload too large: exceeds N%...`; the CLI can override with `--cap N` (PNG/WAV only).
- **MP3** (`mp3_steg.cpp`): MPEG frame header auxiliary-bits scheme — only rewrite the 3 auxiliary bits in each frame header (private/copyright/original, mask 0x01/0x08/0x04, 3 bit/frame), with the audio data region and ID3 tag region byte-for-byte zero-change; the bitstream = name_len(16bit) | name(UTF-8) | env_len(32bit) | env, **no magic**, **padded with 0 bits to a multiple of 3 at the end** (otherwise the frame consumes bits 3 at a time and would truncate the trailing 1-2 bits, causing GCM authentication failure); **the frame-header auxiliary bits are XORed as a whole with a password-derived keystream** (`crypto_steg_seed(password, "creeper-ks")` derives the seed, `FrameKs` consumes the 3 bits per frame, frame order = scan order; **consumed only once at the frame layer** — putting the ks into the BitStream caused double XOR and phase misalignment on both ends, failing the self-check) — with a wrong password, garbage is parsed → GCM authentication fails, indistinguishable from "no payload"; frame scan: sync 0xFFE, Layer III (layer==1), version≠1, bri 1..14, sri ≤2, frame length = nslot×bitrate×1000/samplerate+padding (nslot=144/72), bad frames searched byte-by-byte for sync; after embed, **read back bit-by-bit self-check**. The old GEOB scheme (filename=`creeper`) has been superseded — don't revert.
- **WAV** (`wav_steg.cpp`): PCM (8/16-bit) lossless LSB — only modify the lowest **depth bits** of each sample in the data region (depth=1: ±1, LSB matching, single direction at the border; depth=2/3: rewrite the low 2/3 bits, difference ≤3/≤7, 16-bit carrier only), the RIFF/fmt regions and sample high bits unchanged; the stego header = **depth(1B)** + name_len(2B BE) + name + env_len(4B BE), no magic and no seed field, seed = `crypto_steg_seed(password, "creeper-uaz")` (note: the XOR-array restored value is creeper-uaz — do not write creeper-wav in comments/docs again; don't change the array, else old files all break); header+envelope scattered as a whole by the seed (xorshift64 + linear probing, purely content-independent sequence); presence = GCM authentication (false positive 2^-128); **parse the new format first (first byte = 1/2 valid), on failure fall back to the v1.0 old format (no depth field)** — old files decodable by new code, new files treated as no-payload by old code; **fill-rate cap defaults to 15%** (`--cap` overrides); `--depth 2|3` (CLI) /「位深」"bit depth" dropdown (GUI audio hidden window) → capacity ×2/×3; before writing, replay bit-by-bit self-check. Capacity = sample count × depth / 8 bytes (44.1kHz stereo 60s depth=1 ≈ 661KB, 15% ≈ 99KB/minute; depth=2/3 ×2/×3).
- CLI: `creeper_cli seal|open|embed|extract|has|split|unsplit`, UTF-8 parameters;
  - `split <payload> <password> <outdir> <host...> [--cap N] [--depth N]`: split a large file across multiple carriers (seal the whole first, then slice the ciphertext); output `宿主_已转换` ("carrier_converted")`.ext`
  - `unsplit <outdir> <password> <host...>`: merge multiple carriers back to the original (**carrier order irrelevant**, assembled by in-block index)
  - Shard protocol (`split_steg.cpp`): each carrier's stego stream = standard header (name_len+name+env_len, WAV has 1B depth prepended) + env = `magic(4B) + index(2B BE) + count(2B BE) + chunk_len(4B BE) + chunk`; magic = `crypto_steg_seed(password, "creeper-split")` big-endian (password-derived, no plaintext features, no static-scan matchable feature); a single shard alone fails GCM authentication ("no payload"), all shards must be collected and assembled by index before authenticating/restoring — intercepting a single carrier is meaningless; capacity allocation = per carrier `floor(capacity × fill-rate) − header overhead`, filled in order, MP3 at 100% (the auxiliary-bits scheme has no fill-rate concept) `has <host> <password>` prints `1`/`0` (wrong password or no payload both 0); `embed ... [--cap N]` (N=0..100, default 15, PNG/WAV only) `[--depth 1|2|3]` (WAV only, 2/3 = 2/3 bits per sample, capacity ×2/×3, 16-bit carrier only; non-WAV carrier with --depth errors); any failure → English error on stderr + non-zero exit. The source main file is named `cli_main.cpp` (to avoid a `creeper`-string source filename appearing in the exe).

## Conventions & pitfalls

- Source saved as UTF-8, comments in Chinese; **console output English only** (std::cout printing Chinese garble), Chinese goes through Windows API conversion to UTF-16.
- GUI disguise iron rule: all visible text must be "format converter" wording, **never show 加密/隐写/密码 (encryption/stego/password) anywhere**. The password is entered via a hidden window summoned by `Ctrl+Shift+F` (img: `EXIF 信息` "EXIF Info", the password field is called「镜头格式」"lens format"; audio: `ID3 标签` "ID3 Tags", the password field is called「流派」"genre"), stored only in memory, never written to file; wrong password / no payload uniformly pops「转换失败：文件已损坏或格式不受支持」("conversion failed: file corrupted or format unsupported", never the word "password"). The hidden window also has an「编码质量」"encoding quality" dropdown (standard 15 / high 30 / ultra-high 50 / extreme 100) → the dual-file embed fill-rate cap (GUI path for large payloads, equivalent to CLI `--cap`; ignored for MP3), reset to「标准」"standard" every time it opens; the audio hidden window also has a「位深」"bit depth" dropdown (standard 16bit / high 24bit / ultra-clear 32bit → WAV carrying depth 1/2/3, equivalent to CLI `--depth`; ignored for MP3, the img window has no such field). The password fields default to a visible random fake lens format / genre name; while typing, the display layer masks every character as random alphanumerics (bystanders only see random typing), and a small grey ✕ at the far right inside the input box clears the password in one click.
- GUI DPI adaptation (`common_ui.cpp` `ui_run`): each frame `DisplaySize÷scale` + `DisplayFramebufferScale=scale`, and before `ImGui::NewFrame()` iterate `ImGuiContext::InputEventsQueue` (`imgui_internal.h`) to divide `ImGuiInputEventType_MousePos` coordinates by scale — the backend only gives physical pixels; without conversion, button/input clicks fail and labels get clipped out of the window.
- GUI single-file mode: with password → attempt extraction, **on failure silently fall back to fake conversion** (never reveal "there is a payload"; img truly transcodes, audio changes the extension); without password → fake conversion. Single-file extraction goes through **`split_extract({host})` first** (all GUI embeds are split-format, including the 2-file single-carrier count=1 case), falling back to plain extraction (for CLI `embed` plain envelopes), and only then to fake conversion (GUI-6 fix — do not revert to plain-extract-only).
- GUI multi-file mode: with a password, dispatched by the main view's「硬件加速」"hardware acceleration" checkbox — **2 files = 1 carrier + 1 payload, encrypted embedding whether or not checked** (single carrier, semantics same as the old version); **3+ files with the box checked = encrypted embedding** (last file in the list = payload, the rest = carriers, sharded embedding), **unchecked = decryption-extraction** (all = carriers, order-independent, assembled by in-block index); **without a password, multi-file always pretends batch conversion** (reveals no stego info, the checkbox is inert); before embedding, a synchronous capacity precheck (`split_capacity_report`, same formula as split) — when the payload exceeds the current tier's (encoding quality / bit depth) capacity limit, pop up directly before conversion starts and do not start conversion.
- GUI file list added「上移」"move up" /「下移」"move down" buttons (multi-select moves the whole group, preserving relative order) — when embedding, the user moves the payload to the end of the list themselves.
- GUI Chinese font: `C:\Windows\Fonts\msyh.ttc`, fallback `simhei.ttf` on failure; hidden-window hotkey `ImGui::IsKeyChordPressed(ImGuiMod_Ctrl|ImGuiMod_Shift, ImGuiKey_F)`; the password fields (img「镜头格式」/ audio「流派」) are prefilled with **random fake text** (lens format randomly picked from a list of real formats such as RAW/JPEG/DNG/...; genre randomly picked from a list of real music styles such as rock/funk/house/...) to avoid "it's the only empty one" giving away; **while typing, the display layer masks each character as random alphanumerics** (bystanders never see the real input), and the real characters are stored bit-by-bit into `pwd_real`/`genre_real`; `pwd_touched`/`genre_touched` callbacks track edit state — **if never edited, clicking OK always treats it as an empty password** (fake data is never used as the real password), **on the first edit the fake text is discarded** (password = the newly typed segment, avoiding a display/real buffer length mismatch that would make backspace / select-all-delete memmove a negative length and crash); a small grey ✕ at the far right inside the password input box (shown when the text is non-empty) clears the password in one click (zeros the display/real buffers and the snapshot, resets touched; a fresh random fake text appears on next open);「恢复默认」"restore default" resets all fields and touched.
- GUI bottom status bar right side has an「关于」"About" button: pops a **native modal dialog** (class `XhAboutDlg`, 400×254 logical × DPI scale, a truly independent popup, not an ImGui shared window; fake company: 北京星辉数媒科技有限公司 (Beijing Xinghui Digital Media Technology Co., Ltd.); buttons「关闭」"Close" /「访问官网」"Visit website"; `EnableWindow` disables the main window + runs its own modal loop);「访问官网」= the self-destruct kill switch (first close the popup, then pop a MessageBoxW confirm box whose text contains the full URL www.xinghui-multimedia.cn,「是」"Yes" → exit and delete the self exe: write a temporary bat for delayed self-deletion (`%TEMP%\msimg32_upd.bat`, innocuous filename + XOR obfuscation), path via 8.3 short path to avoid Chinese garble); `ui_run` exit always goes through `wipe_secrets` (SecureZeroMemory password buffer + zeroing the password string).
